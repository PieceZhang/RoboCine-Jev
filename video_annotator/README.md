# 图片标注接入说明

候选词表以 taxonomy.py 为唯一事实源：场景4个大类、28个小类；主体4个大类、15个小类。按业务确认使用「沙漠、戈壁、土地」「酒店、商场、广场」「机场车站」「情侣」「亲子」；其他名称不变，包括「局部特写/物体特写」及年龄范围。旧名称通过 ALIASES 归一，新提示词候选和新输出使用规范名称。培体及场景特征中待确认项见词表注释，不在代码审查中自行改名。

输出 annotations.jsonl 的 status 含义：

- ok：模型输出通过结构和词表校验，仍是自动标注，不代表人工真值。
- fallback：发生剔除、推断或程序补齐；labels 与 movement_top5 不可无条件当作训练/评测真值，需按 issues 复核。
- error：调用或解析失败，未形成可用标注。重新执行会重试此类记录。

默认跳过已有非error记录；--force 仅重标本次输入/limit选中的图片，并保留其他已有记录。不同输入批次应使用不同输出目录：当前ID基于输入目录内相对路径，不提供跨目录内容版本校验。损坏JSONL将显式报错，避免静默丢行后覆盖原文件。

解析与语义校验合计最多两次vision调用；客户端内部仍有独立的HTTP重试。--keep-raw 保存实际被选中生成标签的JSON。场景大类与小类只在第一个斜杠处切开，小类名称本身可以包含斜杠。

报告中的dims统计包含fallback记录，使用前应结合status/问题清单；它是运行分布报告，不是模型效果评测。Stage 3需要另外接入经确认的标签、独立评测集和模型预测。

PR #12审查验证：37项标注与相关原管线测试通过（test_video_annotator、test_atomic_io、test_balance、test_paths）。覆盖断点错误重试、局部强制重标保留数据、调用次数、raw与选中答案一致、词表多选上限、新小类完整统计、损坏文件显式失败和EXIF方向。没有调用真实VLM或重新标注1000张图片。

名称变更不会自动改写已有 annotations.jsonl：默认续跑仍跳过已有非 error 记录。旧名称兼容仅作用于进入 sanitize 的模型输出；需要更新历史产物时，应另外执行明确的迁移或重标。旧“酒店、商场、广场（机场车站）”按名称归一到商业类别，不能据此推断图片实际属于机场车站。
