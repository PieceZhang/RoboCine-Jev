实验配置与场景
CPU 固定积分 20 ms，LiDAR 名义 10 Hz，0.8 s 观测预热，pace=1；官方 https://api.typesafe.ai/v1/systemone，jev-1.14.0。
每次一个 Jev 构造、一个数值候选，候选墙钟预算 6 s，激活提前量 3.2 s；预规划模式增加 --preplan，纯在线无启动前规划。预规划之后仍允许在线监测和重规划。
优化版增加 --reactive-progress。其余实际启动参数和每个四向对照的 task/scene 经自动核对：True，160 次运行、40 个场景。
随机场景来自预先保留的 8 个新种子，4 个单运镜、4 个双运镜，简单/中等各半。每个种子依次派生线性单障碍、非匀速单障碍、多动态障碍、加入地面方块四级；四级共享种子，不能视为 32 个独立样本。
全部 32 个派生场景均重新通过离线 CPU 可行轨迹复核，含完整方块体积和原运镜验收。此证明仅用于场景核查，未发送给 Jev，也未供 agent 执行。L1 的地面穿越修正在最终测试前完成。
离线可行见证是已知完整场景下的存在性证明，不保证仅凭当前观测的在线策略一定可解。
固定集只取 6 个单运镜和 2 个双运镜；4 个三运镜场景按用户限制排除。双运镜缺失连接段由官方 Jev 预先补齐一次，两版/两模式共享同一输入、原阶段时间和总截止时间，不使用旧评测中的额外自由连接时间。因此不能直接把本次固定合计指标等同于历史 12/12。
版本与测试清单在 final_schedule.json 生成时冻结；此后未再根据测试结果调整策略。基线/优化版执行顺序交错，原始日志和每批源码散列均保留。

最终结果
完整通过 = 完成执行 ＋ 原有运镜验收通过 ＋ 独立连续安全和执行器检查通过。
安全完成必须完成全程；中途停止的安全前缀不能计入。独立审核使用 5 ms 采样与速度 Lipschitz 下界，必要时细化到 1 ms；包含停止前最后状态、外部完整体积包络、自碰撞、关节范围和原有 1e-6 绝对执行器残差。
网络未验证单列，不算算法失败。

失败定位
1. 统一配置后，单个线性障碍仍有启动规划拒绝；随机初始构型、相机运动几何与全身分配已能触发数值构造失败。离线存在可行见证，说明局部搜索失败不能解释为场景全局无解。离线见证通过时序调整得到，而启动阶段的单候选接口不提供 body_timing 家族，这也限制了可搜索的解。
2. 在线曲线接续实验曾使候选通过构造，但后续出现激活过期或验证状态邻域失配。较短激活时间与完整验证耗时互相制约；延长提前量又会保留过长的原路径前缀。这些实验没有稳定改善闭环结果，未放宽阈值，也未作为最终改动保留。
3. 多障碍时，部分失败日志显示单独的执行器约束可行，加入当前碰撞约束后局部控制不可行；部分机械臂已接近关节边界。局部让行不能代替更早的全身空间准备和可靠重规划。
4. 已安装的新计划仍可能太晚，且不能抹掉此前的方向/自然曲线违例。安装数不等于任务成功数。
5. test2_L4_boxes 的预规划对照存在一次 API 选择差异：两次完整请求内容相同，基线选择 outer，优化运行选择 adaptive，后者启动构造被拒绝。此时局部控制开关尚未执行。该结果照常保留，说明本批预规划差异还包含官方 API 选择波动；证据见 preplan_api_variation.json。
