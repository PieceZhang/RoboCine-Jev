统一 Representation 验证记录（2026-10-15）

结论
====
选择“两个功能部分 + 每部分最多三个保守盒子 + 两个 6D 变换 + 少量几何关系”
作为当前默认方案。选择依据是相同状态下的几何保真度与文本长度折中，不是已经
证明它在所有机器人或所有避障任务上最优。

双向接口、模型文本隔离、候选/请求绑定、真实 CPU WBC 次级几何目标均已接通。
保留原搜索/配置/候选 Choice、最新状态复核及独立安全求解。没有实现 Memory。

当前六个动态 demo 在两轮 CPU 测试中均完成且通过既有 safety_pass 判据，但
镜头意图完整验收均未通过。较慢调试时钟中 movein、pedestal_up 成功安装新候选；
其余场景主要因现有数值后端未找到可验证候选而继续原控制。不能把这些结果
写成“所有避障问题已经解决”或“新表示提高了镜头成功率”。

测试范围
========
包内完整回归：231 passed。新增 31 项测试，原有 200 项继续通过；既有安装测试
另增加几何请求绑定和篡改拒绝检查。

新增覆盖：
- 倾斜基体的完整 SE(3) 链、XY ZW 四元数约定与 JSON 往返。
- 随机姿态下三个几何预算对所有底层 primitive 的保守包含。
- 球/圆柱/截锥的解析支撑范围；多盒保留空隙而单盒误占的反例。
- 差速、四足、人形、空中平台的合成 FK 合约；无相机调节机构的空几何分支。
- 版本、单位、坐标系、未知字段、非有限数、非法四元数和请求时间拒绝。
- 固定快照系与当前随动坐标系的不同语义。
- 两部分的姿态偏好、区域内占用偏好、远离区域偏好及容差。
- 动态观测的时间对齐/不确定性；空图/过期图保持 unknown。
- Agent 文本不暴露原始关节状态、逐 link 对、执行器或内部 allocation 顺序。
- 超长预览的压缩保留所有选项与完整精确 Request。
- request/observation/camera_path 的绑定，修改偏好后旧 Approval 失效。
- 任意强的几何偏好也不能越过现有相机主任务与安全/执行器硬约束。
- 可行的平台偏好能在相机零空间中降低几何误差。
- 更换相机路径后旧几何引导被清除。

四足、人形、无人机只验证公共数据与坐标语义，不是这些构型的运动控制验证。
没有运行 ROS、PhysX、真实机器人或新视觉网络。

方案对比：1 / 3 / 6 盒
=====================
脚本：scripts/evaluate_representation.py
结果：results/representation_20261015/geometry_ablation/geometry_ablation.json

六个已有 demo，各取 17 个相同的离线 nominal FK 快照，共 102 个。
固定随机种子 20261015，每个状态 2500 个空间探针，按两个功能部分分别判定。
以现有 primitive 几何作为对照；自由阈值为 0.025 m。
障碍真值只用于该离线审计，没有提供给 Agent 或候选生成。

每部分最多盒数   自由探针误占比例   漏占计数   几何文本均值(bytes)   生成均值(ms)
1                5.209%             0          954                   1.760
3                1.977%             0         1245                   1.728
6                1.398%             0         1665                   1.625

平均障碍间隙低估：1 盒 0.109 m，3 盒 0.046 m，6 盒 0.026 m。
3 盒相对 1 盒使误占降低约 62%，文本增加约 30%；6 盒再降低误占，但文本继续
增加约 34%。因此采用 3 盒作默认，并保留命令行预算开关。

“误占比例”是按部件汇总的已知自由探针被代理覆盖的比例，不是任务失败率或
整场景自由体积估计。零漏占是这一采样审计结果；解析外包络构造与包含测试
另提供对已有碰撞代理模型的保守性依据。不能推出未建模真实外形的安全性。
更大的预算减少合并次数，因此本测量中 6 盒生成略快；不要假定单盒生成最快。

两轮真实 Jev CPU demo
====================
本机服务：http://127.0.0.1:8000/v1/systemone，model=perplexity。
均开启原 WBC 避障，原镜头时钟为 8 s，另有 0.4 s 终帧确认。
pace 是 CPU 调试速率上限，不代表墙钟实时能力。

试验 A：boxes3_jev，pace=.2，activation_lead=1.5 s。
六场景均完成，6/6 safety_pass，0/6 intent_success；安装候选 0 条。
API 36 次，无 API 错误。总墙钟约 255 s。
存在候选返回时已过激活时间的情况，不能越过原安装门禁强行执行。

试验 B：boxes3_slow_jev，pace=.1，activation_lead=2.5 s。
六场景均完成，6/6 safety_pass，0/6 intent_success；安装候选 2 条。
API 47 次，其中一次因 8192-token 上限返回 422；总墙钟约 507 s。

文本长度修复与复测
==================
首次候选几何包含五份完整状态，后续请求达到 21531 字符，服务明确拒绝：
Question branch exceeds the 8192-token limit; no input was truncated.

修复为：日志保留完整五个时间快照，模型最多读三个精简相对几何快照；超出
启发式文本预算时仅保留终态预览并明确标注。去掉当前状态反馈中的重复几何。
精确 Request、选项集合和镜头意图不截断，也不舍入输出偏好。
字节预算只是对当前服务的保守启发式，不是任意输入的 token 数保证。

复测目录：results/representation_20261015/compact_final_jev
movein 完成、safety_pass=true、安装 1 个候选；API 8 次，0 次错误。
最大请求 15274 字符，真值最小间隙 0.24569 m，目标位置 RMS 0.00139 m。
intent_success 仍为 false。这一复测确认了实际接口可用，没有证明完整镜头成功。

输出适配器的控制验证
====================
脚本：scripts/debug_representation.py
结果：results/representation_20261015/bridge_base_final

使用远处合成障碍、同一个明确的相机路径、同一复核流程与真实 CPU WBC，
分别开/关几何偏好。这里由确定性规则选候选，不称作真实 Jev 避障效果实验。
两次均成功安装 1 条路径并完成，safety_pass=true；开启时 325 个控制采样评价
几何请求。该路径本来就在偏好死区内，两次残差均为零，所以不能宣称这项对照
改善了轨迹。另一个非零偏好回归测试证明平台能移动并降低残差而保持相机主任务。

性能调试发现，零残差时仍做 16 次差分 FK 会增加无意义的控制计算。修复后在
死区内直接返回零附加代价。对照运行的平均控制循环为 off 23.74 ms、on 24.53 ms；
修复前 on 为 50.29 ms。不同运行受后台计算影响，这只是量级证据，不是实时性证明。
非零残差仍需差分计算，控制循环还有原预测求解的长尾，未承诺 50 Hz 墙钟实时。

迭代中保留的失败记录
====================
bridge_base：数值短名单仅有 continuation，原调试脚本未提供显式修改路径。
bridge_base_v2：已执行控制，但导出缺相机四元数，汇总失败；不计成功证据。
bridge_base_v3：完整输出成功，但零偏好残差仍重复求差分，随后优化。
随机旋转 JSON 往返测试还发现重复归一化四元数会改变末位浮点数和观察 hash；
现改为校验单位长度、仅规范 q/-q 符号，使引用跨序列化稳定。
