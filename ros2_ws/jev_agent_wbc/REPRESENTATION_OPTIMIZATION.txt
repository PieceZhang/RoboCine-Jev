统一 Representation：新候选减少原因与一小时优化记录（2026-10-15）

目标与结论
==========
目标：六个已有差速底盘+机械臂避障 demo 的完整原始镜头意图全部通过。
本轮未达到该目标。候选可执行性、输入长度和恢复链路有改进，但不能把新候选
执行数量增加称作镜头质量整体提升，部分试验的可见覆盖反而下降。
仍未开发 Memory，也未验证其他构型的真实控制器。
开始时间：2026-10-15 05:13:13 UTC。用户时间上限：一小时。
报告生成：2026-10-15T06:13:57.494736+00:00；本轮用时 60.74 分钟。

主要原因及证据
==============
1. 前后试验条件不同。此前无 Schema 报告使用 pace=.05、提前量 1.2 s、数值预算
   8 s；首次 Schema 慢速组使用 .1、2.5 s、2 s。不能把 4/6 到 2/6 全部归因于
   Schema。以优化前统一 Schema 源码重新运行 .05/1.2/8，执行新候选的场景为 3/6。
2. 几何偏好与求解能力误耦合。选择“平台跟随”只试原相机路径的连续实现，只有
   backend_realizable 才能生成显式 FK 替代路径。Jev 改选几何偏好后，实际上丢掉
   了一种关键求解能力。同一源码、六个完全相同的实测状态/观测/前缀、相同 8 s
   协作预算：旧 base 找到候选 1/6，旧 executable 为 5/6。修复后 base 为 5/6。
   三组全部没有预测完整意图通过的候选。实际分支耗时不同，不能称为等 CPU 净收益。
3. 启动太晚。PedestalDown 首次搜索快照约 .76 s，候选到 3.26 s 才可改变相机，
   连续实现却在 3.16 s 已失败；后续 Orbit 搜索也遇到不能修改的前缀失效。
4. 搜索覆盖不足。许多失败只检查了 1/16 条提案，剩余 15 条未试。原接口把失败
   原因合并成“运动未验证”，丢失了时间、失败类别和未检查数量。
5. 已偏离轨迹缺少真实恢复目标。后续一直修改 active 路径，未明确回到原终帧；
   已接受但未恶化的意图缺失还会抑制再次修复。准备分配也被推迟到相机激活后。
6. 三候选请求重复终帧和过程测量，出现 8192-token 服务拒绝。迭代 1/2 的最长
   state 达 23441/23464 字符；去重后迭代 3 最长 16426 字符，87 次调用零错误。

已实现
======
- Schema 增加小型 task_context：原参考、时间、截止、最早可改变时刻、前缀风险、
  是否需要恢复；不暴露 joint、逐 link、执行器或动力学。
- 公共反馈保留有限失败类别、首次失败时间、未试数量与搜索是否完成。
- 几何偏好不再决定是否允许后端生成可执行替代相机轨迹；仍由 Jev 选择精确候选，
  再经原来的状态、FK、碰撞和执行约束检查。
- 相机前缀不变的情况下，可提前跟随已批准的冗余准备；几何偏好变化不误判为空操作。
- 明确恢复到 immutable original 的连续位置/姿态路径，支持精确日志回放。
- 增加固定截止时间内的非对称时间分配、不同方向候选和保持运动坐标的尺度补偿。
  先比较镜头后果和无障碍实现先验，再进行昂贵的完整几何验证；先验从不充当证书。
- 预测可见性使用名义观测几何/速度，显式 guarantee=false；未来不确定范围不再
  被视为真实不透明实体。物理碰撞包络仍按原规则增长，实测镜头验收完全不变。
- 文本只省略可选预览和重复测量；所有选项、失败事实和精确 Request 保留。

没有采用的方案
==============
较长时域几何预引导、额外平台绕行分配、严格光轴约束的局部投影均做过诊断。
平台分配 72 个局部严格尝试均未验证通过；光轴投影 8 个尝试均未通过完整物理
求解。全时域投影虽然部分能生成安全候选，过程偏离仍大。未将这些未证实有益的
控制器原型并入交付。其源码与失败记录保留在结果目录，失败不是全局无解证明。
在无障碍诊断中，六条原参考都能通过连续实现，说明原参考本身不是普遍不可执行；
难点在动态障碍下同时完成整机分配、相机过程和终帧约束。
