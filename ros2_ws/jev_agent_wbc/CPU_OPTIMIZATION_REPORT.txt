实现
1. 单候选连续构型检查从约 211 个节点减少至本次每例 58 个（最大间隔 0.15 秒）。
   每段保留中点 FK、奇异值、关节/轮子速度和加速度约束，以及整机扫掠下界。
   自碰撞从三个区间采样开始，仅在保守下界不能判定时局部细分至最多 33 点。
   相机几何仍进行 50 Hz 扫掠与区间最近接近检查，镜头验收阈值保持原值。
2. 联合曲线优化使用 13 个构型节点、最多 8 次 SQP，曲线采用一个 Jev 指定的解析种子。
   64 个独立廉价相机探测点补足粗节点之间的快速障碍穿越。最后仍须完整独立数值门槛通过。
   不重复进行相机预优化；初始安装沿用第一阶段的严格同状态、同观测、同路径见证复用。
   所有场景统一将 typed construction 的 tempo 从 2 调整为 4，为冗余构型准备留出余量。
   最终仍由新的官方 Jev 请求选择，离线修改已存决策的实验不计作正式验收。
3. 已批准轨迹在线构型诊断使用向前至少 2 秒的滚动窗口，避免重新求解整条冗余轨迹。
   剩余全程相机安全、镜头意图、实际误差和每步硬安全证书仍检查。
   构型预测、传感器模拟/地图融合、周期几何反馈在独立进程中执行，控制线程只非阻塞读取结果。
   每类最多一个未完成任务，保留采集时间、顺序、过期拒绝与已有陈旧观测制动规则。
4. 批量正运动学、解析碰撞距离/法向、雅可比、相机位姿和几何偏好差分；
   严格凸小 QP 的无约束最优解只有通过全部原约束时才直接采用。
   同一状态的机械臂 FK 可复用；所有缓存按完整几何输入精确匹配，并保护返回值所有权。
   进程传输不携带增长的采样缓存，预测只返回计算结果；诊断日志在后台预序列化。
   几何反馈保留采集时间及请求绑定；文件写入有序异步执行，关闭时排空，不丢弃证据。
   数值后台进程在支持的系统中 nice +5，仅降低子进程优先级，不改变系统实时调度策略。
   当已求得的相机任务精确可行点证明障碍余量足够时，跳过重复的最优余量 LP；
   报告明确区分可行点下界和 LP 最优值，所有执行器行重新检查，其他情况仍求原 LP。
   后台进程启动在镜头时钟之前完成，启动与 API 时间另行记录。

计时口径
planner_wall_s 包含唯一候选的生成、联合优化、全部数值检查与几何描述，
不包含官方 API 网络/推理等待、进程预热和初始传感校准。
generation_optimization_wall_s 单独报告种子生成加联合优化，不能替代完整规划时间。
iteration_compute_wall_s 覆盖主循环内传感结果接收、engine.step、真值诊断、记录与积分，
只排除主动 pace 等待。control_thread_wall_s 是其中 engine.step 部分，CPU 时间另列。
50 Hz 对应 20 ms。严格阶段二标记要求每例所有记录的完整主循环步骤 <=20 ms，
且完整规划 <1 秒；不能用 P99 或均值代替最大值。所有性能试验串行 demo，BLAS/OMP 单线程。
这是普通 Linux 用户态测量，不是实时内核的最坏时限保证。

复现
README.md 给出官方闭环命令。benchmark_directed_cpu.py 可从任意已保存官方闭环
读取构造决策进行离线 CPU 数值回放；输出明确标记没有新的 API 调用或执行验收。
analyze_directed_jev.py --independent 检查单候选计数、模型来源、正式镜头、独立安全和延迟。
JEV_AUDIT_CODE_ROOT 可指定冻结的第一阶段 Python 包根目录，用原碰撞实现交叉审计。

限制
结果限定于这六个 demo、明确记录的随机扰动范围及 CPU 运动学闭环。
不宣称任意初态/障碍都能一次选对，也不将模拟 LiDAR、几何图像指标当作 RGB、PhysX 或实机验证。
第一阶段的性能数据来自六例并行，第二阶段最终数据来自串行，不直接报告未经控制的倍数加速。
