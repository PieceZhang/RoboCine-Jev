# 2026-10-20 CineGym / PhysX 限时调试

本轮在 3 小时 PhysX 优化上限内执行，使用官方 TypeSafe `jev-1.14.0`，100 Hz 物理、50 Hz 控制调度、`pace=1` 和原始物理相机。**完整运镜高成功率目标未达成：冻结完整方案仅 1/40 通过。** 这是真实 PhysX 仿真，没有实机验证。

三组使用同一批 40 个随机场景：20 easy、20 medium，28 个单运镜、12 个双运镜，混合动态球体与不同尺寸的落地箱体。全部通过同一个实测相机审计器复核；没有网络未验证或缺少产物的正式场次。基线为本轮 PhysX 的起点，已包含前一轮 CPU 改动，仅额外转发在线启动参数以兼容相同协议。

物理安全计数包括停止后的运行，不代表任务完成；完整方案仍有 15 场原生接触和 1 场安全余量不足。三组高层计划实际安装数均为 0。完整方案方向、曲线质量和终帧检查分别失败 26、36、33 场，计数可以重叠。逐场控制计算 p95 的中位数为 66.39、33.45、38.52 ms，说明物理循环按时并不等价于整个异步控制链具备 50 Hz 硬实时保证。

早期六场景 strict/Jev 配对 CPU 开发组位于 `/tmp/jev_v2_final_cpu`：12 次中 10 次跑到原始终点，8 次同时跑到终点并通过安全检查，固定几何阶段完成标准下 **0/12 within_budget_success**。所有 Jev 运行均未安装修复。truck_right 两次提前退出，Orbit 两次安全检查失败。该组尚未显式提供相机内参，也早于时间戳浮点误差和精细安装预测修正；保留为诊断证据，不能称为最终版基准。

随后 MoveIn 的定点复核均保持安装门禁：

- `/tmp/jev_v2_verified_movein`：真实 Jev 批准，最新状态超出预测邻域，拒绝安装。
- `/tmp/jev_v2_fine_cpu`：安装前采用 0.02 s 近端预测，验证结果到达时已超过精确激活时刻，拒绝安装。

这些结果说明安装审计能暴露问题，**不能说明动态修复已经有效**。不能为得到安装记录而修改批准轨迹时刻、放大状态容差或强迫模型接受候选。

## 调试中修复的关键问题

1. Jev 请求超过服务每问题 8192 token 限制：移除重复完整对象，改为简洁后果卡、短别名和一次最终 Choice；精确绑定仍留在程序与日志。
2. 粗筛在修改激活前打分会使所有提案相同：改为共享前缀之后筛选，再预测有限分支。
3. 安装复核的粗时间步长导致近端状态偏差：前 1.2 s 使用 0.02 s 步长，后缀仍用 0.1 s；过期继续拒绝。
4. 浮点时间减法产生微小负年龄：只容忍 `1e-8 s` 数值误差，真实未来/过期数据仍拒绝。
5. 失败候选生成未进入统计分母、连续感知反馈可能推迟事件：均已修复并添加回归。
6. RGB 参考切换污染：独立参考渲染＋帧数协议＋掩膜质量复核。
