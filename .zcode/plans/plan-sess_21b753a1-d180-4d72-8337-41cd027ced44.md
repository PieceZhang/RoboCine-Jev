ilton# 批量 ik_stream + retime 数学批量化（step ⑤ 18s → ~5-7s）

## 0. 先 profile（只读，确认估计）
用 cProfile 拆 step ⑤：_retime_per_segment / ik_stream / check_trackable 各占多少（当前为结构推断：ik_stream ~12-15s、retime 循环 ~2-5s）。若 ik_stream 实际占比 <60%，重估方案收益再动手。

## 1. 批量 ik_stream（jarvis_batched.py 扩展）
新增 `ik_stream_batched(samples, sdf, caps, allow_unreachable, hold_segments)`：
- **逐采样点批内并行**（跨样本必须串行：prev_q/prev_branch 线程依赖）——每个采样点把全部底盘候选（θ₀ × offset × d，经 SDF/房间预过滤）× 种子集 [prev_q, mid, rng₁..rng₄] 展开为一个 batch（与顺序版种子集完全一致，parity 成立）；
- 选取规则镜像顺序版：prefer 序（先 prev_branch 的 θ₀ 与 d）取**首个收敛候选**；无收敛 → 复刻"冷重试"路径（种子集 [mid, rng₁..rng₅]，无 q0）；仍无 → failure 或 hold（arc 驻足）语义原样；
- jarvis_export.ik_stream 变分发器（ROBOCINE_IK_SEQUENTIAL=1 强制顺序版），export 主流程不改。

## 2. 批量 retime 数学（retime.py / jarvis.py 扩展）
- `_aligned_jacobian` 批化：参考 J 闭式已知，yaw 重对齐是旋转矩阵乘——所有方向一次 batch；`v_max` 的 pinv 批量算（torch.linalg.pinv 一次 N 个 6×8）；
- `vertex_speed_limits` / `interval_factor` 换批量实现，PlatformCaps 接口不变；
- Caps 值、收敛语义零改动（纯加速，可精确对拍）。

## 3. parity 测试 + 基准（tests/test_jarvis_batched.py 扩展）
- ik_stream：真实 kid_combo 重定时流上 configs/failures/holds 与顺序版逐行一致（q 允许 1e-9 浮点差，base/d/yaw_offset 应精确一致）；
- v_max/twist_factor：随机方向网格上与顺序版逐值一致（atol 1e-9）；
- 端到端基准：/tmp 复跑 step ⑤，记录 18s → ?；全 pipeline 数字更新。
